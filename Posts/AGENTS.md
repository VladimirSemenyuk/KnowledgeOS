# Правила работы с публикациями

## Главное правило

Посты пишет Владимир, вручную. Агент не генерирует, не дописывает и не переписывает тексты постов, заголовки и крючки, даже если попросят «чуть улучшить». Если просьба похожа на генерацию, уточнить, какая из функций ниже нужна. Исключение — сценарии Reels, пункт 5 ниже.

## Каналы

- Основные: Instagram, LinkedIn, Threads.
- Вспомогательный: Telegram.

Контекст, аудитория и воронка — в [[Posts/Context|Posts/Context.md]]. Позиционирование и метод — только в [[Personal/Context|Personal/Context.md]].

## Что агент делает

1. **Материал из встреч.** По запросу достаёт из `Clients/**/summary.md` наблюдения: формулировки клиентов, повторяющиеся ситуации, факты, вопросы. Без тезисов, углов и готовых формулировок для поста. Каждое наблюдение обезличено и со ссылкой на источник.
2. **Архив публикаций.** Заводит заметку опубликованного поста в `published/` по шаблону [[Templates/posts/post.template|post.template]]: текст вставляется как есть, без правок. Обновляет [[Posts/content-index|content-index]].
3. **Проверка по запросу:**
   - типографика — skill `apply-typograf`, только кавычки, тире и пробелы;
   - конфиденциальность — не узнаётся ли клиент, компания, сумма, внутренняя ситуация;
   - повтор — не было ли уже поста на эту тему (сначала `content-index.md`).
   Результат проверки — список замечаний. Правки в текст вносит автор.
4. **Блокнот идей.** Записывает идеи автора в [[Posts/ideas|ideas.md]] по его просьбе: формулировка автора, одна идея — одна строка. Может предлагать свои идеи, но добавляет их только после одобрения автора.
5. **Сценарии Reels.** По просьбе автора собирает связный сценарий из его тезисов: крючок и формулировки автора — дословно, агент только связывает их и укладывает в хронометраж. Автор говорит в кадре своими словами. Решение автора, 2026-11-17. Подписи к Reels и тексты постов под исключение не попадают.

## Чего агент не делает

- Не предлагает серии и контент-план, если не попросили. Идеи — по правилу «Блокнот идей». Действующий контент-план — [[Posts/content-plan|content-plan.md]]; изменения в нём — только по решению автора.
- Не правит стиль, структуру и тон.
- Не считает охваты и не импортирует аналитику платформ.

## Папки и файлы

- `content-plan.md` — ритм, список недель со статусом, цель, учёт, правила съёмки и монтажа. Единственный источник правды; при расхождении другие файлы уступают ему, кроме этого `AGENTS.md` и `Personal/Context.md`.
- `ideas.md` — блокнот идей автора; агент пополняет его по просьбе автора.
- `drafts/` — черновики автора, если он хранит их здесь.
- `published/` — опубликованные посты, одна заметка — один пост. Одинаковый текст в нескольких каналах — одна заметка, все ссылки в frontmatter.
- `content-index.md` — индекс для навигации и проверки повторов.
- `weeks/<дата>-<тема>/_index.md` — неделя контент-плана: таблица публикаций по дням и каналам, все тексты и сценарии Reels недели, картинки, отметки «не хватает». Один файл на неделю, отдельные файлы с текстами не заводятся. Рядом — только картинки недели, по подпапкам каналов.
- `render/` — общие скрипты: рендер слайдов (`render.py`), тексты слайдов всех недель (`slides/instagram.py`, `slides/linkedin.py`, поле `week` задаёт папку недели), монтаж Reels (`reel.py`), выгрузка медиа в Cloudflare R2 для Buffer (`upload.py`, ключи — в `.env.r2` вне git) и отложенная публикация в Telegram-канал с заменой и удалением запланированных постов (`tg.py`, ключи и сессия аккаунта — `.env.tg`, `.tg.session` вне git).

Посты до 16 ноября 2026 опубликованы в LinkedIn и размечены по архивной воронке TOFU/MOFU/BOFU. Разметку не менять.

## Конфиденциальность

Не раскрывать имена клиентов, детали встреч, коммерческие условия, юридическую и финансовую информацию без явного согласия.

Наблюдения из клиентской работы обобщать:
- роль вместо человека;
- закономерность вместо события;
- структурная проблема вместо частной детали.
